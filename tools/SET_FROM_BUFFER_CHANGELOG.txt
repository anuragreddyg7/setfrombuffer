adapter.go - SetFromBuffer implementation (uses valkey.BinaryString):
// SetFromBuffer sets the value of a key using a []byte buffer.
//
// For performance this implementation uses valkey.BinaryString(buf) which
// performs a zero-copy conversion on Go 1.20+ (it uses unsafe under the
// hood). This avoids allocating a separate string for large payloads.
//
// IMPORTANT: Because this is a zero-copy conversion the caller MUST NOT
// mutate the provided buf while the command is in-flight. If caller-safety
// is preferred instead of allocation avoidance, call with a copy of the
// buffer or use a wrapper that does `string(buf)`.
func (c *Compat) SetFromBuffer(ctx context.Context, key string, buf []byte) *StatusCmd {
    // Use library helper which returns a binary-safe string view of buf.
    // This is faster for large payloads but relies on the caller not
    // modifying buf concurrently while the command may be sent.
    value := valkey.BinaryString(buf)

    cmd := c.client.B().Set().Key(key).Value(value).Build()
    resp := c.client.Do(ctx, cmd)
    return newStatusCmd(resp)
}


Architecture and coding decisions taken:
- Performance vs Safety: The implementation uses valkey.BinaryString(buf) which performs a zero-copy conversion to string (uses unsafe internally). This favors performance (no allocation/copy for large payloads) but requires the caller not to mutate the buffer while the command is in-flight. We documented this contract in the method comment. If callers prefer safety, they should call SetFromBuffer with a copied buffer (or we can add a safe alternative API).
- API stability: We added SetFromBuffer to the public `CoreCmdable` interface and propagated the API to `Pipeline` wrappers so existing call sites can be updated uniformly. This was necessary to keep the package interfaces consistent.
- Testing strategy: The added tests are mock-based (gomock) to avoid requiring live services for unit validation. Integration tests remain running against docker-compose where available.
- Developer ergonomics: Added `tools/run-tests.sh` to standardize bring-up/wait/test/teardown flows. The script can be adjusted to skip Docker for unit-only runs.
